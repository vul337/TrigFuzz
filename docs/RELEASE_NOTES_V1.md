# TrigFuzz v1 Release Notes

## Included

- AFLGo based TrigFuzz implementation under `engines/aflgo-trigfuzz`.
- Selective AFL++ based TrigFuzz implementation under `engines/aflplusplus-selective`.
- Python TCU generation, instrumentation, validation, and example driver.
- Explicit `distance_expr` metadata path for generated TCUs.
- Small runnable examples and focused tests.

## Defaults

- AFLGo based TrigFuzz defaults to triggering-distance scheduling and `+trig` queue discovery.
- Triggering byte-aware mutation is an optional config:

```sh
export AFL_TRIG_ENABLE_BYTE_AWARE_MUTATION=1
```

- The Python driver uses AFLGo `-z exp -c 10m` by default and passes `-d` when `--quick-dirty` is used.

## Known Scope

- The Python driver is a compact prototype driver, not a full campaign manager.
- Large Magma campaign scripts and raw evaluation artifacts are not part of this release tree.
- The AFL++ selective path expects a conservative keep list generated by the user or by external analysis.
